# Story engine

The authoritative reference for how stories are written (Yarn Spinner 3), rendered, saved and observed.
Source: `src/engine/`, `src/events/`, `src/persistence/`, `tooling/yarn/`.

Runtime: [`yarnspinner-typescript`](https://www.npmjs.com/package/yarnspinner-typescript) (community TypeScript port of
Yarn Spinner 3; pinned to an exact version — review its changelog before upgrading). The project is compiled at build
time; the browser only ships the runtime and the compiled program.

## Story layout

```
src/stories/<id>/
  index.ts                     StoryDefinition: meta, dialogue, startNode, images, audio, links
  dialogue/<id>.yarnproject    standard Yarn project file (projectFileVersion 4); sourceFiles globs stay inside the folder
  dialogue/*.yarn              one file per chapter; nodes are global across files
  images/*.webp                generated by `npm run images`, plus dimensions.json
  audio/music/*.opus           looping tracks  (opus/ogg/mp3/m4a)
  audio/sfx/*.opus             one-shot effects
```

Register the story in `src/stories/registry.ts`; select it with `?story=<id>`. `startNode` is the node a new game
starts at. Assets are found by file name: `images/tablet.webp` → `<<image tablet>>`, `audio/music/tension.opus` →
`<<music tension>>`. The official Yarn Spinner VS Code extension understands the `.yarnproject`.

## Pages

A **page** is everything Yarn delivers up to the next option set (`->` options). Choosing replaces the page (no
scrolling transcript). A page's `path` is the node where it started. Options whose condition is false
(`-> Texto <<if $x>>`) are hidden.

## ⚠ Colons

Yarn reads `Texto: resto` as *speaker: line*. In narration write every `:` as `\:` — **including inside markup
values** (`[tip text="Pista\: es un acertijo"]`). If a line does have a speaker it is shown as a bold `Speaker:`
prefix, and the escape walkthrough test fails on any unintended speaker or unparsed markup.

## Build checks

`npm run dialogue:check` (also run by `npm run build` and CI) compiles every project and fails on:

- Yarn errors, reported as `file:line:col CODE: message`.
- **Jump loops without content**: a cycle of `<<jump>>`/`<<detour>>` with no line, command or options in between
  (e.g. a node that only does `<<jump>>` to itself). The Yarn runtime runs jumps in one synchronous loop, so such a
  cycle would freeze the tab. A cycle that only happens for some variable values (behind an `<<if>>`) is a warning.
- Source files outside the project folder, including via symlinks.

## Commands (effects)

| Command | Effect |
|---------|--------|
| `<<scene key>>` / `<<scene none>>` | Header image from this page on (persistent). |
| `<<music key>>` / `<<music stop>>` | Crossfades background music (persistent). Missing files are ignored with one warning. |
| `<<sfx key>>` | Plays once when the page appears. |
| `<<image key "caption">>` | Image at this point in the text; consecutive `<<image>>` commands form a gallery. Click opens a lightbox. Caption is also the alt text. |
| `<<hint "summary">>` | The **next line** becomes a hint: `summary` is the button, the line is the revealed text. |

Unknown commands produce a warning (dev console) and are ignored. Yarn's own commands (`<<set>>`, `<<declare>>`,
`<<jump>>`, `<<if>>`, `<<stop>>`, …) work as usual.

## Line tags

Tags go at the end of a line: `Texto #heading #block:postit`. A tag cannot contain spaces.

| Tag | Effect |
|-----|--------|
| `#heading` / `#subheading` | Renders the line as `h2` / `h3`. |
| `#block:postit\|list\|olist\|note\|clue` | Consecutive lines with the same style form one group (post-it, bullet list, numbered list, dashed note, cipher/monospace clue). |
| `#input:variable` | The line is the label of an answer control. Optional `#kind:text\|password\|code\|keypad` and, for keypads, `#length:n` (default 4, max 12). The page must have **exactly one** option (the submit button). On submit the trimmed answer (max 200 chars) is stored in `$variable` (declare it with `<<declare>>`), then the option is taken. `code` = text field with numeric mobile keyboard; `keypad` = combination lock with digit dials, 0-9, ⌫ and `#`; only exactly `length` digits are accepted (enforced by the engine too). |
| `#outcome:fail` | Styles the page as a failure and counts it in `stats.failures`. |
| `#ending:id` | Names the ending; reported in `story.ended`. The story ends when Yarn finishes (no more nodes to run). |

## Markup

Yarn's native markup, rendered as React nodes (HTML in story text is always shown literally):

| Markup | Result |
|--------|--------|
| `[b]texto[/b]` | bold |
| `[link key=libros]texto[/link]` | external link to `links.libros` in the story definition (https only, new tab). Only allow-listed URLs can be opened. |
| `[tip text="Pista"]texto[/tip]` | toggletip: hover, focus+click or tap shows the text; Esc closes. |

## Answers

Compare answers in Yarn. `==` is case-sensitive (`$respuesta == "TenedoR"`). For forgiving matches use the bound
function `normalize()` — lower case, no accents, spaces or punctuation (`normalize($respuesta) == "marialuisagonzalez"`).

## Saves

- Autosave to `localStorage` (`story-game:save:<id>`) at the start of every page. Yarn has no state snapshot, so a save
  is the **list of decisions** (option indexes and submitted answers) plus stats and playtime.
- Resuming replays those decisions on a fresh dialogue, rebuilding variables and presentation. This requires the story
  to be **deterministic**: don't use `random()`/`dice()` for outcomes that affect later choices.
- Saves carry the compiled program hash; editing the Yarn scripts invalidates old saves. A save that no longer replays
  (e.g. an option was removed) is discarded.
- Loaded saves are validated (`isSaveGame`) — storage is untrusted input. Storage failures never break the game.
- Swap storage by implementing `SaveRepository` (`src/persistence/save-repository.ts`) in `src/app/services.ts`.

## Events

Every meaningful action is published on the event bus as a `StoryEventEnvelope`
(`id`, `type`, `storyId`, `sessionId`, `seq`, `at`, `payload`); see `src/events/types.ts`.

| Type | When |
|------|------|
| `session.started` | new game or resume (`resumed`, `storyHash`) |
| `page.shown` | every page (`path` = node name, `outcome`, `choiceCount`) |
| `choice.made` | option taken (`path`, `index`, `text`) |
| `input.submitted` | answer submitted; `value` omitted for `password` inputs |
| `hint.revealed` | first time a hint is opened on a page |
| `variable.changed` | Yarn variable changed (input variables and `Yarn.Internal.*` excluded; replayed pages are not re-reported) |
| `story.ended` | ending reached, with playtime and stats |
| `story.error` | runtime error; the UI offers to retry from the last save |

Sinks: dev console in development; set `VITE_EVENTS_ENDPOINT` (same-origin path or https URL) to POST batches
`{ "events": [...] }` via `sendBeacon` (flushed every 5 s, at 25 events, and when the tab is hidden). Listener failures
are isolated from the game. `id` is an idempotency key for the backend.
