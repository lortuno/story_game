# Story engine

The authoritative reference for how ink stories are written, rendered, saved and observed.
Source: `src/engine/`, `src/events/`, `src/persistence/`, `tooling/ink/`.

## Story layout

```
src/stories/<id>/
  index.ts             StoryDefinition: meta, ink, images, audio, links
  ink/main.ink         root file; INCLUDEs chapters (paths relative to ink/, cannot leave the story folder)
  ink/chapters/*.ink
  images/*.webp        generated by `npm run images`, plus dimensions.json
  audio/music/*.opus   looping tracks  (opus/ogg/mp3/m4a)
  audio/sfx/*.opus     one-shot effects
```

Register the story in `src/stories/registry.ts`. Select it with `?story=<id>`.
Assets are discovered by file name: `images/tablet.webp` → `# image: tablet`, `audio/music/tension.opus` → `# music: tension`.

## Pages

A **page** is everything ink outputs up to the next choice point. Choosing replaces the page (no scrolling transcript),
which keeps the DOM small and matches the original escape-room flow.

## Tags

Tags go at the end of a content line (`Text # tag # key: value`). Tag-only lines attach to the *next* line in ink, so
always anchor tags to text. Unknown tags produce a warning (dev console) and are ignored.

| Tag | Scope | Effect |
|-----|-------|--------|
| `# heading` / `# subheading` | line | Renders the line as `h2` / `h3`. |
| `# block: postit\|list\|olist\|note\|clue` | line | Consecutive lines with the same style form one group (post-it note, bullet list, numbered list, dashed note, cipher/monospace clue). |
| `# image: key` | line | Adds an image after the line. Several `image` tags on one line = gallery. Click opens a lightbox. |
| `# caption: text` | line | Caption + alt text for the preceding `image` tag. |
| `# hint: summary` | line | Moves the line out of the text into the hints panel: `summary` is the button, the line is the revealed hint. |
| `# input: variable [text\|password\|code\|keypad] [length]` | page | The line becomes the label of the answer control. The page must have **exactly one** choice (the submit button). On submit the trimmed answer (max 200 chars) is stored in the global `VAR variable`, then the choice is taken. `code` is a text field with a numeric mobile keyboard. `keypad` is a combination lock: `length` digit dials (default 4, max 12) beside a 0-9 pad with ⌫ and `#` (submit). Only exactly `length` digits are accepted, enforced by the engine as well as the UI. Physical keys 0-9, Backspace, Enter and # also work. |
| `# scene: key` / `# scene: none` | persistent | Header image from this page on. |
| `# music: key` / `# music: stop` | persistent | Crossfades background music. Missing files are ignored with one warning. |
| `# sfx: key` | page | Plays once when the page appears. |
| `# outcome: fail` | page | Styles the page as a failure and counts it in `stats.failures`. |
| `# ending: id` | page | Names the ending (use with `-> END`); reported in `story.ended`. |

Separators: ink forbids a bare `|` in content, so tags use spaces (`# input: respuesta password`) and separate tags
(`# caption:`) instead.

## Inline markup

| Markup | Result |
|--------|--------|
| `**text**` | bold |
| `[label](key)` | external link to `links[key]` in the story definition (https only, new tab). Keeps URLs out of ink — `//` starts a comment in ink — and only allow-listed URLs can ever be opened. |
| `[label](?tip text)` | toggletip: hover, focus+click or tap shows `tip text`; Esc closes. |

Markup is parsed into React nodes; HTML in story text is always shown literally.

## Answers

Compare answers in ink. Exact match is case-sensitive (`respuesta == "TenedoR"`). For forgiving matches use the bound
external `normalize(text)` — lower case, no accents, spaces or punctuation (`"María Luisa González."` →
`"marialuisagonzalez"`). Declare it with `EXTERNAL normalize(text)` plus an ink fallback function so the story also runs in Inky.

## Saves

- Autosave to `localStorage` (`story-game:save:<id>`) at the **start** of every page: ink state JSON + presentation +
  stats + playtime. Resuming replays the page deterministically.
- Saves carry the compiled story hash; editing the ink invalidates old saves (discarded on resume).
- Loaded saves are validated (`isSaveGame`) — storage is treated as untrusted input.
- Storage failures (private mode, quota) never break the game.
- Swap storage by implementing `SaveRepository` (`src/persistence/save-repository.ts`) in `src/app/services.ts`.

## Events

Every meaningful action is published on the event bus as a `StoryEventEnvelope`
(`id`, `type`, `storyId`, `sessionId`, `seq`, `at`, `payload`); see `src/events/types.ts`.

| Type | When |
|------|------|
| `session.started` | new game or resume (`resumed`, `storyHash`) |
| `page.shown` | every page (`path` = `knot.stitch`, `outcome`, `choiceCount`) |
| `choice.made` | choice taken (`path`, `index`, `text`) |
| `input.submitted` | answer submitted; `value` omitted for `password` inputs |
| `hint.revealed` | first time a hint is opened on a page |
| `variable.changed` | ink global changed (input variables excluded) |
| `story.ended` | ending reached, with playtime and stats |
| `story.error` | runtime error; the UI offers to retry from the last save |

Sinks: dev console in development; set `VITE_EVENTS_ENDPOINT` (same-origin path or https URL) to POST batches
`{ "events": [...] }` via `sendBeacon` (flushed every 5 s, at 25 events, and when the tab is hidden). Listener failures
are isolated from the game. `id` is an idempotency key for the backend.
